# Start, Continue, and Submit an Attempt

Candidate delivery is a coordinated Session and WebSocket workflow. A generic
backend integration must not invent an Attempt or continuity credential: the
privileged candidate coordinator receives them through authenticated
`exam_attempt.connect` admission on the versioned WebSocket protocol.

## 1. Establish the Candidate Session and Socket

Sign in with an interactive Session, then <Link to="/api/reference/connect-web-socket">connect the WebSocket</Link>.
The first eligible `exam_attempt.connect` lazily creates the candidate's single
Attempt for the Sitting, its copy-on-write Workspace, a Participation
generation, and one current Connection. Retain the returned values only in the
protected runtime:

- `exam_attempt_id`
- `participation_id` and `generation`
- `connection_id`
- the 32-byte continuity credential
- renewal interval and lease expiry

The exact connect, renewal, focus-loss, acknowledgement, and error envelopes
are part of the versioned WebSocket protocol, not HTTP request bodies. Never
send the continuity credential in a URL, form field, or log.

## 2. Read the Presentation

For protected HTTP requests, combine the candidate Session with the two attempt
headers:

```bash
curl --request GET \
  --url https://proctor.example.edu/api/v1/exam-attempts/<attempt-id>/presentation \
  --header 'Authorization: Bearer <interactive-session-access-token>' \
  --header 'X-Proctor-Attempt-Credential: <continuity-credential>' \
  --header 'X-Proctor-Attempt-Connection-ID: <connection-id>'
```

<Link to="/api/reference/get-candidate-exam-presentation">Get candidate presentation</Link>
resolves the Sitting's current immutable Revision. Retrieve protected resources
through their attempt-scoped content routes.

## 3. Persist Workspace Changes

Every Workspace mutation includes `participation_id` and `generation`; uploads
put those values in the `metadata` part. Preserve each acknowledged Workspace
cursor and content version. Use an idempotency key where the endpoint requires
it.

```json
{
  "participation_id": "<participation-id>",
  "generation": 2,
  "path": "answers"
}
```

Use <Link to="/api/reference/list-candidate-exam-workspace-changes">Workspace changes</Link> to
reconcile acknowledged mutations after a recoverable client interruption.

## 4. Renew or Reconnect

The privileged coordinator explicitly renews the Participation with monotonic
sequences at the server-provided interval. WebSocket ping does not renew it. A
brief reconnect may retain the generation; an expired or interrupted
generation is fenced permanently and requires fresh admission. If the Attempt
is suspended, a manager must re-allow it before a new generation can begin.

## 5. Submit Against Acknowledged State

Submit only after the client has received acknowledgements for its final
Workspace mutation and focus-loss signal.

```json
{
  "participation_id": "<participation-id>",
  "generation": 2,
  "expected_workspace_cursor": 18,
  "final_focus_loss_sequence": 3
}
```

<Link to="/api/reference/submit-exam-attempt">Submit Exam Attempt</Link> atomically seals the
Workspace and returns a candidate-safe receipt. Retry an uncertain result only
with the exact request and idempotency key. Submission unbinds the Attempt
runtime but leaves the ordinary authenticated socket available.
