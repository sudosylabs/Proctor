# Set Up an Institution

Every Proctor installation contains one Institution. Its academic hierarchy,
identity policy, and scoped authority provide the context in which examinations
are created and delivered.

<Maturity state="preview">
  The administrative server contracts are implemented, but the complete visual
  administration journey is not. Use this guide to understand the model; use the
  API guide for current integration work.
</Maturity>

## Establish the Structure in Order

1. **Bootstrap the Installation and Institution.** The first protected setup
   establishes the installation identity and initial administrative authority.
2. **Create Academic Units.** Model faculties, schools, departments, or other
   hierarchical organizational units.
3. **Define Programmes and Programme Levels.** Programmes belong to their
   academic context; levels describe progression within them.
4. **Open Academic Periods and Classes.** A Class is the concrete student roster
   for a Programme level in an applicable Academic Period.
5. **Configure identity and onboarding.** Choose allowed login paths, admission
   rules, and invitation behavior before bringing people into the institution.
6. **Grant roles through scoped bindings.** Affiliations and memberships record
   relationships. They do not themselves grant unrestricted permissions.

## Keep 3 Concepts Separate

| Concept | What it expresses | What it does not imply |
| --- | --- | --- |
| Affiliation | A person's relationship with the Institution | Permission to administer every resource |
| Membership | Placement in an Academic Unit or Class | An unrestricted role |
| Role Binding | Permission at Institution, Academic Unit, or Class scope | Ownership outside that scope |

## Important Vocabulary

Use **Class**, not Group, for the concrete roster. Use **Exam Manager** for an
Exam's creator or another teacher with equal management authority. “Proctor” is
the product name and does not silently grant a person a special role.
