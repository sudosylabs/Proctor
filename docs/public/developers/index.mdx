# Develop With Proctor

Proctor is a Go workspace with four independently versioned modules and one
hosted React application. Repository development connects them; every Go module
must still build and test without workspace assistance.

<Maturity state="preview">
  This is the first public developer entry point. Exact setup and command
  authority remains in the module READMEs and root build guide while the public
  contribution journey is expanded.
</Maturity>

## Choose the Owning Module

| Module | Owns |
| --- | --- |
| `packages/cache` | Reusable cache contracts and adapters |
| `packages/mail` | Reusable mail composition and delivery contracts |
| `packages/vfs` | Reusable virtual-file-system contracts and adapters |
| `server` | Proctor domain, application, transports, persistence, and composition |
| `webapp` | The hosted browser application |

Reusable packages never import server types. Business logic remains independent
of HTTP, WebSocket, SQL, Redis, SMTP, VFS, Memberlist, and concrete adapters.
The module-root `server.New` function is the only composition root that selects
infrastructure.

## Contribution Rule

Make the smallest coherent change, add tests proportional to risk, and update
the authority that owns any changed domain language, architecture, public
contract, capability status, or command. Generated documentation must name its
tracked input and rebuild deterministically.
