# Operate Proctor

One Proctor installation represents one Institution. A single application node
and an active-active group use the same product semantics. Horizontal scaling
changes infrastructure redundancy, not authorization or feature availability.

<Maturity state="preview">
  Packaging, configuration validation, hardened systemd and container examples,
  TLS modes, node lifecycle, serving leases, health, metrics, logs, Memberlist,
  and pre-release recovery boundaries are implemented. This is pre-production
  guidance, not a certified production support matrix.
</Maturity>

## Follow the Operating Path

1. [Verify a package or image](./package-and-install.mdx) and its embedded
   binary/hosted-application identity.
2. [Create protected configuration and secret inputs](./configuration-and-secrets.mdx)
   and validate them before any listener starts.
3. Choose the tracked [systemd or container runtime](./systemd-and-container.mdx)
   without weakening non-root and read-only boundaries.
4. Select [single-node or active-active topology](./topology-and-dependencies.mdx)
   and assign PostgreSQL, Redis, VFS, SMTP, execution-host, and load-balancer
   responsibility.
5. Configure [TLS and reverse-proxy behavior](./tls-and-proxy.mdx), including
   the separate metrics and cluster boundaries.
6. Route traffic by [readiness and observable evidence](./health-and-observability.mdx),
   not process existence.
7. Use the bounded [maintenance and recovery procedures](./maintenance-and-recovery.mdx)
   that are implemented today.
8. Stop at the explicit [pre-production limits](./pre-production-readiness.mdx)
   instead of inventing sizing, backup, upgrade, or support promises.

## Authority at a Glance

| Dependency | Durable responsibility |
| --- | --- |
| PostgreSQL | application state, authorization facts, audit, leases, Jobs, mail state, Workspace metadata |
| VFS/S3 | opaque managed bytes selected through PostgreSQL metadata |
| Redis | disposable shared cache and installation-wide counters in cluster mode |
| Memberlist | best-effort peer discovery and effect propagation, never durable state |
| SMTP | transport acceptance for durable mail delivery, not application truth |
| Execution hosts | isolated, replaceable Attempt Workspace projections |

PostgreSQL commits before cache invalidation, peer fan-out, WebSocket
publication, execution projection, or SMTP delivery. A failure of a transient
effect is recovered by durable state and refetch, not by treating that effect
as the source of truth.
