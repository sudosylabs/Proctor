# Execution Configuration

Execution hosts are operator-managed infrastructure that run exam work outside
the application process. Proctor loads one bounded, immutable host catalog at
startup. Every change on this page requires restarting each application node;
partial catalog rollout can make placement behavior inconsistent.

## Service controls

| Path and default | Meaning and accepted value |
| --- | --- |
| `Execution.Enabled`<br />Default: `false` | Enables operations that depend on execution hosts. At least one valid host is required when `true`. |
| `Execution.DialTimeout`<br />Default: `10s` | Maximum time to establish an outbound execution-host connection. Must be greater than zero and no more than `1m`. |
| `Execution.OperationTimeout`<br />Default: `30s` | Default deadline for an execution-host operation when the use case supplies no shorter deadline. Must be greater than zero and no more than `5m`. |

The host list may contain at most `64` entries. A disabled execution service may
retain a validated catalog, which supports deliberate staged enablement.

## Host catalog

Each object in `Execution.Hosts` identifies one trusted endpoint. The tracked
[`execution-host.json`](https://github.com/sudosylabs/Proctor/blob/main/server/config/examples/execution-host.json)
shows the complete object shape. Replace its placeholder credential before use.

| Path and default | Meaning and accepted value |
| --- | --- |
| `Execution.Hosts[].ID`<br />Default: no hosts | Stable placement identity. Must be unique and contain `1`–`64` ASCII letters, numbers, dots, underscores, or hyphens. Changing the address does not change this identity; changing the ID creates a different placement target. |
| `Execution.Hosts[].Address`<br />Default: no hosts | Outbound endpoint in `host:port` form, with port `1`–`65535`. |
| `Execution.Hosts[].Security`<br />Default: no hosts | Connection profile: `tls` for authenticated encrypted transport, or `insecure_local` for an explicitly loopback-only development endpoint. |
| `Execution.Hosts[].Token`<br />Default: no hosts | Endpoint bearer credential, up to `512` bytes without control characters. Required for `insecure_local`; for `tls`, configure a token, a client certificate, or both. Secret. |
| `Execution.Hosts[].ServerName`<br />Default: no hosts | TLS name verified against the execution host certificate. Required with `tls`; forbidden with `insecure_local`. |
| `Execution.Hosts[].CAFile`<br />Default: no hosts | Optional PEM trust-anchor file for `tls`. Leave empty to use the system trust store. Forbidden with `insecure_local`. |
| `Execution.Hosts[].ClientCertificateFile`<br />Default: no hosts | Optional PEM client certificate for mutual TLS. Must be configured together with `ClientKeyFile`; forbidden with `insecure_local`. |
| `Execution.Hosts[].ClientKeyFile`<br />Default: no hosts | Private key paired with `ClientCertificateFile`. Secret; protect it with service-account file permissions. |

### TLS profile

Use `tls` for every non-loopback host. `ServerName` is mandatory. The client
certificate and key are an all-or-nothing pair, and at least one application
credential—token or client certificate—is required. A custom `CAFile` adds the
private trust root needed by an internally issued server certificate.

### Insecure local profile

`insecure_local` exists for local development. Its address must resolve to a
literal loopback host, its token is mandatory, and all TLS-related fields must
be empty. It is not accepted as a shortcut for private production networks.

## Rollout checklist

Before enabling or changing the catalog:

1. establish the execution host and issue purpose-specific credentials;
2. verify address resolution and certificate names from every application node;
3. distribute the same catalog and secret material to every node;
4. run `proctor config validate` on the effective configuration;
5. restart nodes using the installation's controlled rollout procedure; and
6. verify dependency health before allowing exam work to depend on the host.

Validation checks local shape and trust requirements. It does not dial the host,
verify its certificate chain, or confirm that its credential is authorized.
