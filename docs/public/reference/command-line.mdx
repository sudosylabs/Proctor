# Proctor Command-Line Reference

The CLI is a thin caller of server capabilities. It does not implement a second
policy path. Run `proctor help` or command-specific `--help` from the exact
release binary for localized usage and the current flag surface.

Every command accepts `--config` (short form `-c`). An explicit path wins over
`PROCTOR_CONFIG` and the default `config/config.json`.

## Commands

| Command | Purpose | Starts the server? |
| --- | --- | --- |
| `proctor serve` | run migrations/startup reconciliation, dependencies, Jobs, WebSocket, HTTP, readiness, and bounded shutdown | yes |
| `proctor config validate` | strictly load and validate effective configuration | no |
| `proctor config show` | print the effective configuration with every secret redacted | no |
| `proctor migrate status` | compare database and server schema versions and report pending migrations | no |
| `proctor migrate up` | apply every pending migration deliberately | no |
| `proctor migrate down` | revert an explicit number of the newest migrations while every node is stopped | no |
| `proctor cluster status` | list serving node leases, cluster discovery rows, and the schema version | no |
| `proctor jobs list` | list the newest durable Jobs with state, attempts, last error code, and availability | no |
| `proctor jobs show` | show one Job and its most recent attempts | no |
| `proctor administrator recover` | host-only administrator local-authentication recovery while all nodes are stopped | no |
| `proctor administrator reset-mfa` | reset an existing administrator's MFA and require reenrollment while all nodes are stopped | no |
| `proctor version` | print build version, commit, build time, and Go version | no |

## Serve and Validate

```sh
proctor config validate --config /etc/proctor/config.json
proctor serve --config /etc/proctor/config.json
```

`serve` integrates with systemd notification when `NOTIFY_SOCKET` is present.
The first SIGTERM or SIGINT starts a graceful drain, a second forces it to
finish at once and makes `serve` exit with status 1, and a third exits
immediately. SIGHUP reloads configuration and static TLS certificates.
The CLI warns when run as root; use a dedicated non-root service account.

## Show Effective Configuration

```sh
proctor config show --config /etc/proctor/config.json
proctor config show --json --config /etc/proctor/config.json
```

`config show` loads and validates configuration exactly as `config validate`
does: built-in defaults, then the file, then `PROCTOR_` environment
overrides. It prints one `Path = value` line per setting, with values in their
JSON spelling, preceded by a comment naming any environment variables that
replaced a file value. `--json` prints the whole document in the configuration
file's shape instead. Every secret is replaced by `[redacted]` in both forms:
the database data source, Redis password, metrics bearer token, Memberlist,
mail sealing and MFA key rings, SMTP password, S3 credentials, bootstrap
secret, and OIDC client secrets. An empty secret stays empty, so the output
shows whether a secret is set without revealing it. The command connects to no
dependency and never writes the file.

## Database Migration

```sh
proctor migrate status --config /etc/proctor/config.json
proctor migrate up --config /etc/proctor/config.json
```

The current pre-release baseline does not support upgrading older incompatible
development schemas. Status does not certify backup, rollback, or production
upgrade safety.

### Reverting Migrations

```sh
proctor migrate down --steps 1 --config /etc/proctor/config.json
proctor migrate down --steps 1 --confirm --config /etc/proctor/config.json
```

`migrate down` reverts the newest `--steps` applied migrations; the count is
required and must not exceed the applied migrations. It first prints the
current schema version, each migration it would revert, and the resulting
version. Without `--confirm` it stops there, reverts nothing, and exits with
status 1. It refuses while any serving node holds a live lease, naming the
nodes; stop every node and wait for a crashed node's lease to expire first.
While reverting it holds the migration lock and the serving-node lease fence,
so no node can start serving or migrate meanwhile.

Proctor currently ships one pre-release baseline migration, so `--steps 1`
reverts to version 0: an **empty schema**. Every Proctor table and all of its
data is dropped; only Morph's own `db_migrations` and `db_lock` bookkeeping
tables remain, and only a database backup brings the data back. The command
says so before it acts. A node started afterwards applies the baseline again
and starts from an empty installation. Rollback is never a startup action.

## Read-Only Inspection

`migrate status`, `cluster status`, `jobs list`, and `jobs show` only read. They open the database with
every session set to `default_transaction_read_only`, so PostgreSQL itself
rejects any write. They never migrate, never take the migration lock or
another advisory lock, and never create a table, so they are safe to run
beside serving nodes and do not require the schema to match the binary.

```sh
proctor cluster status --config /etc/proctor/config.json
proctor cluster status --json --config /etc/proctor/config.json
```

`cluster status` prints the database and server schema versions with the
pending migration count, the PostgreSQL time, and two tables. **Serving
nodes** lists every serving node lease with its node ID, state, renewal time,
expiry, and lease ID; a node may serve only while its lease is `live` by the
PostgreSQL clock, and an `expired` row belongs to a node that stopped without
withdrawing its lease. **Cluster discovery** lists the Memberlist bootstrap
rows with advertise address, server version, and protocol range; these rows
are disposable and written only by the `memberlist` cluster backend, never by
`local`. Expired rows are shown rather than hidden. Each list stops at 500
rows and says so. A database with no schema reports no nodes.

```sh
proctor jobs list --config /etc/proctor/config.json
proctor jobs list --state failed --type mail.deliver,mail.cleanup --limit 20
proctor jobs show <job-id>
proctor jobs show <job-id> --json
```

`jobs list` prints the newest Jobs first, at most `--limit` of them (default
50, at most 200), with ID, type, state, attempts used of the maximum, last
public error code, the time the Job is next available to a worker, and the
last update. `--type` and `--state` are repeatable or comma-separated and
accept only known values; the error for an unknown value lists them. States
are `queued`, `running`, `cancel_requested`, `succeeded`, `failed`, and
`canceled`. Unlike the administrator API, host listing includes internal Job
types. When more Jobs match, the output says so; narrow the filters rather
than paging. `jobs show` adds creation, start, completion, and progress
times and the 20 most recent attempts with node, heartbeat, lease expiry, and
error code.

Neither command prints a Job's command, checkpoint, result, deduplication
key, or an attempt's claim token, because those can carry user identifiers or
content. Both refuse a database without a schema. `--json` writes the same
fields for automation. To cancel or retry a Job, use the administrator Jobs
API, which authorizes and audits the change; the CLI never changes Jobs.

## Host-Only Administrator Recovery

Stop every application node first. Confirm the exact Institution and active
system-administrator User. Choose at least one recovery action:

```sh
proctor administrator recover \
  --config /etc/proctor/config.json \
  --institution-id <institution-id> \
  --user-id <user-id> \
  --enable-local-login \
  --rotate-password
```

`--rotate-password` reads the new password from private standard input; a
password is never a positional argument or flag. The operation writes a durable
recovery record while transports and workers remain stopped. Restart normally
so Proctor reconciles its audit record. Other flags are `--institution-id`,
`--user-id`, and `--enable-local-login`.

For a lost authenticator, use the separately named MFA reset command:

```sh
proctor administrator reset-mfa \
  --config /etc/proctor/config.json \
  --institution-id <institution-id> \
  --user-id <user-id>
```

MFA must be enabled and configured. The target must be an active system
administrator with an existing permitted primary authentication method.
The command accepts no password, recovery code, or factor proof. It retires
old MFA material, revokes the target's Sessions, PATs and unfinished access
grants, and records a mandatory reenrollment restriction with durable host
recovery evidence. It preserves primary credentials and the Access Policy.

Restart normally to reconcile the audit record. Then sign in with fresh
password or provider proof and enroll a new authenticator. An external-only
administrator must use an already linked, permitted provider; restore that
provider first if it is unavailable. Disabling MFA does not lift the recovery
restriction. A second host recovery command is rejected until the pending
record has been reconciled. After a crashed node, wait for its serving lease
to expire before retrying either command.

## Build Identity

```sh
proctor version
proctor version --json
```

Use `--json` for automation. Compare the binary identity with the release
manifest and packaged hosted application before deployment.
