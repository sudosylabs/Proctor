# Review Proctor Security

This review path separates controls Proctor enforces from controls an
installation operator must supply. It describes implemented boundaries and
explicitly marks product or production policy that has not been decided.

<Maturity state="preview">
  The server controls described here are implemented and checked against current
  code and configuration. Retention and purge schedules, legal hold, support
  windows, stable deprecation, and a production encryption-at-rest policy beyond
  existing operator and secret-sealing boundaries remain undecided.
</Maturity>

## Follow the Review Surface

1. [Threat model and trust boundaries](./threat-model.mdx) defines protected
   assets, actors, assumptions, and control ownership.
2. [Credentials and authorization](./credentials-authorization.mdx) maps
   credential proof and assurance separately from action/resource permission,
   concealment, and durable audit.
3. [Data and privacy](./data-privacy.mdx) classifies credentials, student and
   Exam data, diagnostics, integrity evidence, and redaction.
4. [Keys, certificates, and network](./keys-network.mdx) assigns Desktop, MFA,
   mail, Memberlist, TLS, listener, and outbound dependency responsibility.
5. [Content and execution](./content-execution.mdx) covers VFS, Workspace,
   Submission, Browser Activity, and execution-host isolation.
6. [Errors, limits, and compatibility](./errors-limits-compatibility.mdx)
   explains fail-closed public errors, bounded inputs, compatibility, and safe
   recovery.

## Core Security Properties

- Authentication establishes an immutable principal; it never embeds a
  reusable permission snapshot.
- Every application action resolves current authority on the canonical
  resource and records required audit durably.
- PostgreSQL is authority for durable state. Cache, cluster, realtime, and
  execution projections are reconstructible.
- Credentials, secrets, Exam answers, student content, private Review fields,
  and unbounded input stay out of ordinary logs and unsafe audit fields.
- Candidate delivery requires a registered-key Desktop Session plus the exact
  current Attempt continuity fence.
- Integrity signals are bounded evidence with explicit uncertainty, not a
  verdict or academic outcome.
