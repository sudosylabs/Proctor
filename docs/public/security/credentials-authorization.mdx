# Credentials, Assurance, Authorization, and Audit

Credential validity, credential assurance, and resource permission are three
separate decisions. A strong recent Session can still lack authority. A Role
cannot make a Personal Access Token satisfy an interactive-Session route.

## Credential and Proof Matrix

| Credential | Transport proof | Intended use | Important ceiling |
| --- | --- | --- | --- |
| Browser Session cookie | HttpOnly cookie; CSRF and allowed Origin on unsafe requests | hosted interactive account and administration flows | current Session assurance and route declaration |
| Bearer Session access credential | `Authorization: Bearer` | non-cookie Session clients where the route permits | cannot satisfy registered-key Desktop requirement |
| DPoP-bound Desktop Session | `Authorization: DPoP` plus fresh signed `DPoP` proof and nonce | Desktop discovery, realtime, protected candidate delivery | proves registered client request, not Exam permission |
| Personal Access Token | bearer token plus action and academic-subtree ceilings | explicit API automation | rejected by interactive-only and candidate-delivery routes |
| Refresh credential | purpose-specific rotation endpoint | rotate an existing Session credential family | not a general application principal |
| Bootstrap secret | exact pristine-installation bootstrap proof | create the one Institution and first administrator | permanently useless after atomic bootstrap |
| Invitation or recovery claim | purpose-specific one-use browser exchange | accept invitation, verify email, reset password | never a reusable Session or general bearer token |
| Attempt continuity credential | sensitive header plus current Connection selector, under DPoP Session | exact Participation generation operations | fenced by Attempt, Session, Participation, generation, and Connection |

Credential sources are mutually exclusive where declared. The server does not
pick a preferred identity from mixed cookie, bearer, and DPoP inputs.

## Assurance Is a Route Ceiling

Routes declare public, principal-required, interactive Session, strong, recent,
strong-and-recent, refresh, or composed proof requirements. Strong assurance
derives from the authentication method and MFA state. Recent assurance derives
from bounded authentication time. Both are checked before the application use
case, but neither grants permission.

The checked route/OpenAPI agreement keeps runtime credential declarations,
OpenAPI `security`, and `x-proctor-auth` aligned. The
[API authentication guide](/api/guides/authentication) is the consumer-facing
counterpart.

## Authorization Uses Current Resource Facts

The use case combines the immutable principal, stable action, canonical
resource, current account state, applicable Role Bindings, academic scope,
intrinsic ownership or management relationship, resource lifecycle, and token
ceilings. It reads current PostgreSQL facts immediately before protected work or
mutation.

Role Bindings are additive and deny by default. Scope inherits only through the
defined Institution, Academic Unit, and Class structure. Candidate participation
is a current relationship-and-state decision rather than a general Role grant.

## Conceal Protected Existence

For another User's private data, unauthorized Exam, Sitting, Attempt,
Submission, file, or unreleased result, existence may be sensitive. The owning
use case maps denied, missing, mismatched, inactive, or out-of-scope selectors
to one not-found shape where the contract requires concealment. Internal cause
does not enter the response.

## Audit Required Decisions Durably

Audit is PostgreSQL security evidence, not an operational log. Safe events use
bounded actor, action, canonical resource, scope, outcome, request/node
correlation, time, and approved projections. Credentials, Exam answers, content,
provider payloads, private rationale, and unbounded input are excluded.

Where audit is required, an unavailable audit path fails closed. Critical
mutations either commit state, audit, and retained idempotent outcome together,
or use a durable attempt-to-terminal protocol whose incomplete state remains
operator-visible.
