# Content, Workspace, and Submission Security

PostgreSQL decides what content means and who may access it. VFS stores opaque
bytes. None of those outer
systems can grant application authority from an object key, path,
or local filesystem state.

## Managed Content

Uploads are bounded before and during streaming, content-typed from bytes, and
staged under private unguessable keys. Required inspection and renditions finish
before a named Store operation makes metadata Available. Unknown database
outcomes retain staged objects until reference-aware cleanup can prove deletion
safe.

Protected downloads authorize semantic metadata before opening bytes. They
return explicit media type, length, ETag, private/no-store cache policy, and
`nosniff` behavior. Proctor does not expose public or signed object-storage URLs.

## Attempt Workspace and Submission

Workspace paths are normalized, bounded, case-sensitive POSIX-relative metadata.
Traversal, links, devices, sockets, and `.proctor` candidate writes are denied.
Every mutation fences current Participation, generation, credential, Session,
Connection, expected entry/path/version state, and Attempt-scoped idempotency.

Submission pins acknowledged logical entries and content versions without
duplicating bytes. Managers can inspect the immutable Submission only after
sealing and cannot read live Workspace content. Candidates receive a safe
receipt and do not browse the sealed manifest or files.

## Governed Browser

The governed Browser follows a frozen allowlist and records minimized top-level
activity. Browser page content does not enter evidence.
